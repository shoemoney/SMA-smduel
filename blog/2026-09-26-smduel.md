# 963 passing tests and no way to earn money

*2026-09-26 — building a browser vehicular-combat RPG from scratch in a day*

I set out to measure whether a fleet of agents could build a real game. By evening the suite
was green — 963 tests, clean typecheck, successful production build — and the game had **no income
path at all**. Both ways a player earns money were finished, well tested, and called by nobody.

```
grep -rn '\bdeliver\b'            src/ (excl. its own file)  ->  0 hits
grep -rn 'recordOpponentDefeated' src/ (excl. its own file)  ->  0 hits
```

You could accept a cargo job, be charged a day for it, drive across the map to the destination,
walk into the depot — and find no way to hand the cargo over. Every arena event that paid required
defeating opponents that were never spawned, so a match could only ever end in forfeit.

The tests were not bad. The simulation was correct and thoroughly covered. **The layer that was
supposed to call it did not exist**, and unit tests import modules directly, so nothing noticed.

That is the day's lesson, and it cost most of the day to learn: *a test suite cannot see a function
nobody invokes.* Coverage tooling doesn't help — the function **is** covered, by its own tests. What's
missing is an edge in the call graph from somewhere a player can reach, and no green run reports its
absence.

## The method that actually found things

Reading tests did not work. I read a lot of tests and they looked fine.

What worked was **breaking the code on purpose and checking whether anything screamed.** Every
finding below came from a mutation, not a review.

The first sweep was humbling. Three separate things that had been reported as fixed, verified, and
committed turned out to be decorative:

| Mutation | Result |
|---|---|
| Hardcode the session seed, ignoring `?seed=` entirely | **all 681 tests passed** |
| Re-hardcode 5 of 6 casino constants back into TypeScript | **passed** |
| Revert the atlas config to its 17 MB regime | **passed** |

Those tests existed. They ran. They protected nothing.

## The arena was fielding unarmed couriers

The worst one. A full "victory" in the beginner arena ended with the player having taken **literally
zero damage**, and the suite called it a win.

Opponent selection picked purely by value band from an archetype pool I had written for the *highway*,
where non-combatants belong. So the arena was selecting `runner` — a courier whose only mount is a
rear smokescreen — and had `beater`, which has no weapons at all, in scope. The player was fighting
cars that could not shoot.

The only assertion about player survival was `expect(player.destroyed).toBe(false)`, which an untouched
player satisfies for free.

So I wrote a test: *the player genuinely takes fire.* It summed armour before and after and asserted
it dropped. It passed. **It also passed with the fix reverted** — because collision damage lowers
armour too, and the player was being *rammed* by retreating unarmed cars, not shot.

My test's name said gunfire. My test's assertion said "lost armour somehow." Collision damage in this
codebase lands on exactly one facing and never touches tires or the power plant, so the fix was to
assert damage somewhere collision cannot reach.

That is a distinct failure mode from a tautology, and I hadn't had a name for it before: **an
assertion a different mechanism can satisfy.** The test can genuinely fail against *some* break and
still not test the thing it is named for.

## Then I broke it a second way, with my own fix

Adding a combat-capability gate fixed the selection. I wrote a test. The mutation — deleting the gate
— kept passing.

Cause: the same fix had also added a new entry-level archetype, and its value band (`0–5376`) **entirely
contained both non-combatants' bands**. With overlapping bands resolved by array order, no input value
could select a weaponless car any more. The guard was real, correct, and permanently unreachable —
which is indistinguishable from absent.

I had made my own protection untestable with the data change that shipped alongside it. Narrowing the
band to bracket its own cost restored a value range where a non-combatant genuinely wins, after which
removing the gate failed two named tests.

## Things I reported wrong

Worth keeping in, because these are the ones that would have quietly become false history.

**I claimed a 69% atlas reduction. It was 3.4%.** I measured `atlas-0.png` and reported it as the
total, while 3.7 MB sat in `atlas-1.png` that I hadn't looked at. The split that produced those two
sheets was itself a regression: the loader only ever fetched sheet one, and the bundler never emitted
sheet two, so `tsc`, the full suite and the production build were **all green while the game could
render 16 of its 50 frames.**

**I reported "704 passed" from a stale file.** This machine has `noclobber` set, so `> /tmp/v.txt`
*failed* on an existing file and the next line grepped the *previous* run's output. The number was
real; it just described a run that had happened earlier. The same trap ate a heredoc later and made me
re-run a diagnostic script that had already been superseded, so I spent two minutes reasoning about a
conclusion that described a previous state of the repo.

**I wrote two `expect(X).toEqual(X)` tautologies** — while in the middle of fixing tautologies. Caught
them before committing, but only because I was already looking.

## The run that produced nothing

One six-module fan-out came back with all six agents reporting success and **zero files written.**

Mid-run, a message arrived asking an unrelated question about licensing. It reached the agents. Five
of six answered the licensing question instead of building their module. One said so outright in its
report: *"I did not run the big courier-loop build task... your actual message this turn was just this
atlas question, so I answered that instead."*

The expensive part wasn't the wasted build stage. It was that **every downstream stage trusted the
report**: reviewers produced 60+ findings about modules that did not exist, fix agents "fixed" them,
and the integrator had nothing to integrate. Four stages passed the lie along.

What caught it was a gate returning mutations as **INAPPLICABLE** rather than SURVIVED. You cannot
mutate code that was never written — and that turns out to be a better signal than a survived mutation.

The vaccine was two sentences in the prompt plus one proof obligation: ignore anything that isn't your
task, and paste `ls -la` of every file you were asked to write. An agent that wrote nothing cannot
produce that listing. Re-running the identical workflow with those added produced all six modules —
793, 587, 315, 300, 222 and 150 lines, plus 13 more files — where the first attempt produced one.

## What I'd keep

The adversarial review stage earned its cost: **16 of 16 modules failed review, 152 findings, all
fixed.** A clean sweep of PASS would have been the suspicious result.

The release gate earned more. It caught the integrator claiming a provenance ledger was complete when
six entries were missing, and it's the reason "no income path" was found at all rather than shipped.

But the thing I'd actually keep is the habit: **green means nothing until you've broken it on purpose.**
Every real defect today was found by mutation. Not one was found by reading.

flips, somebody looks at it on purpose.*
